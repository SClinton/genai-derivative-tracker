Scan schedule & control

Scan now

Triggering a scan requires calling the GitHub Actions API with a token that can write to this repo — not something this page will ever hold, for the same reason it never holds your search API keys (see the notice at the top). This button takes you to GitHub's own Actions page instead, where Run workflow uses your existing GitHub login, not a credential typed into a static site.

Open Actions → Run workflow

The Run workflow form on that page has two optional fields, date_from and date_to (YYYY-MM-DD) — a historical scan restricted to that date range instead of the default (today/most-recent, no restriction). Leave both blank for a normal scan. This is a real filter on Google search, a best-effort prompt hint on Perplexity/Parallel (they don't support a hard date filter), and not applied to YouTube at all (different, not-yet-wired-up filter mechanism) — see the code comments in crawler/engines.py for the exact per-engine behavior.

Prefer the command line? gh workflow run "Crawl for derivative works" --repo SClinton/genai-derivative-tracker -f date_from=2022-01-01 -f date_to=2023-12-31

Change the schedule

Reading .github/workflows/crawl.yml…

Same reasoning as above — changing the schedule means editing and pushing a file in the repo, which this page can read but not write to safely. Edit the cron: line in .github/workflows/crawl.yml (cron is always UTC) and push; it takes effect on the next scheduled run.

Common schedules to copy in

# Daily at 13:00 UTC - cron: "0 13 * * *" # Twice a week -- Monday and Thursday at 13:00 UTC - cron: "0 13 * * 1,4" # Weekly on Wednesday at 09:00 UTC - cron: "0 9 * * 3" # Monthly, the 1st at 13:00 UTC - cron: "0 13 1 * *"

Double-check any custom expression at crontab.guru before pushing — a typo here just means the crawl silently doesn't run on the day you expected, GitHub won't warn you.

Upgrade paths

SerpAPI paid plan Same key — no new credential

Covers Google, Bing, and DuckDuckGo search. The free tier is 100 searches/month, which is why serpapi_engines is narrowed to just google, most languages are gated off via region_groups, and conference_search is disabled — see crawler/queries.yaml for the exact cost-math comments next to each setting.

To upgrade

  1. Upgrade your plan at serpapi.com/pricing. Your existing SERPAPI_KEY keeps working — nothing to re-set as a GitHub secret.
  2. In crawler/queries.yaml, re-enable coverage to match your new quota:
# Add more SerpAPI sub-engines (each one multiplies query count): serpapi_engines: - google - bing - duckduckgo # Flip a whole region back on (its individual language `enabled:` flags decide which ones within it actually run): region_groups: Europe: true # Re-enable the conference/association discovery pass (was ~81% of total query volume): conference_search: enabled: true

Commit and push — the next scheduled run (or a manual Actions → Crawl for derivative works → Run workflow) picks it up automatically.

Perplexity Same key — billed per request already

Perplexity has no separate free/paid tier to toggle — it's billed per request from the start on the same PERPLEXITY_API_KEY. "Upgrading" here just means checking your spend against how many queries you're running (titles × enabled languages, currently shown above) and adjusting queries.yaml if needed.

Check current usage/billing at perplexity.ai/settings/api.

Parallel.ai Search API Requires a new credential

AI-native semantic search — catches paraphrased mentions a literal keyword search might miss, and is currently the only engine here that returns a per-result publish date (every other engine leaves the candidate's date empty, falling back to today's date at Quick-add time). No confirmed free tier — billed from the first request, roughly $0.36/month at this project's current scope (18 titles × 1 language, basic mode, $5/1,000 requests).

To enable

  1. Get a key at platform.parallel.ai.
  2. Add it as a GitHub Actions secret yourself (I won't ask for or handle the value):
gh secret set PARALLEL_API_KEY --repo SClinton/genai-derivative-tracker

parallel is already enabled in crawler/queries.yaml's engines: list — it'll just start working once the secret is set, no other config change needed.

Google Cloud Translation API Requires a new credential

Only needed if you want translate_modifiers: true — translating generic terms like "presentation"/"training course" into each enabled language to catch paraphrased mentions, not just exact-title hits.

To enable

  1. In Google Cloud Console, enable the Cloud Translation API for a project (can reuse any existing project).
  2. Create an API key under APIs & Services → Credentials.
  3. Add it as a GitHub Actions secret yourself (I won't ask for or handle the value):
gh secret set GOOGLE_TRANSLATE_API_KEY --repo SClinton/genai-derivative-tracker
  1. Set translate_modifiers: true in crawler/queries.yaml.

Quick reference

Check which secrets are currently set (names only, never values)

gh secret list --repo SClinton/genai-derivative-tracker

Set or replace a secret

gh secret set SECRET_NAME --repo SClinton/genai-derivative-tracker

Remove a stale secret

gh secret delete SECRET_NAME --repo SClinton/genai-derivative-tracker

Trigger a crawl run manually

gh workflow run "Crawl for derivative works" --repo SClinton/genai-derivative-tracker
